# Справки по отраслям

Одна справка — один файл `<id>.yaml`. Уклон — в отдел продаж: наши клиенты в первую очередь хотят автоматизировать продажи.

## Поля

| Поле | Зачем |
|---|---|
| `id`, `title`, `group` | id совпадает с именем файла, группа — для списка отраслей |
| `status` | `full` — полная справка, `short` — пока только основа, дописать |
| `markers` | начала слов, по которым бот узнаёт отрасль в ответах первого блока анкеты. Можно фразы: `разработк сайт` найдёт «разработка сайтов». `$` в конце — только целое слово: `сто$` найдёт «СТО», но не «стоимость» |
| `sales_model` | кому и как продают: клиенты, тип сделки, цикл, чек, повторные продажи |
| `lead_sources` | откуда обычно приходят клиенты |
| `funnel` | типичные этапы сделки — основа воронки в CRM |
| `sales_roles`, `documents`, `terms` | кто продаёт, какие документы, на каком языке говорит клиент |
| `sales_pains` | где обычно болит в продажах — что проверить в ответах |
| `other_pains` | боли вне продаж, коротко |
| `automation` | что обычно автоматизировать в продажах |
| `questions` | дополнительные вопросы бота: ключ — id вопроса анкеты, после которого спросить. `skip_if` — если клиент уже сказал одно из этих слов, вопрос пропускается |
| `avoid` | чего не спрашивать |

## Как бот использует справку

1. После каждого вопроса первого блока («Знакомство») бот ищет `markers` в ответах. Побеждает справка с наибольшей суммарной длиной найденных маркеров.
2. Дальше к вопросам анкеты добавляются вопросы из `questions` — после базовых углубляющих вопросов.
3. Отрасль попадает в файл ответов (`industry` в JSON и строка «Отрасль» в Markdown).

Остальные поля пока для ручного разбора и отчёта, позже их будет читать нейронка.

## Новая справка

Скопировать похожую справку, поменять поля, добавить пример описания бизнеса в `SAMPLES` в `tests/test_industries.py` и запустить тесты: `python -m unittest discover tests`.
