# biz_analyzer

Сервис разбора бизнеса: клиент проходит интервью, из ответов собирается модель бизнеса, а из неё — майндкарта, BPMN-схемы процессов и отчёт с узкими местами.

## Как устроено

```
интервью (questionnaire.yaml)
        ↓
модель бизнеса (JSON по business_model.schema.json)
        ↓  core/validate.py — проверка схемы и ссылок
        ├─ core/mindmap.py → майндкарта (Markdown, рендер через markmap)
        ├─ core/bpmn.py    → BPMN 2.0 XML по каждому процессу (своя авторазметка)
        └─ core/report.py  → HTML-отчёт для клиента
```

| Папка | Что внутри |
|---|---|
| `schema/` | Схема модели бизнеса и анкета интервью |
| `core/` | Проверка модели и генераторы |
| `examples/` | Демо-модели для проверки генераторов |

## Запуск

```bash
pip install -r requirements.txt
python -m core.build examples/flower_delivery.json -o out/flower_delivery
```

Результат в `out/flower_delivery/`:
- `report.html` — отчёт, открыть в браузере (нужен интернет: markmap и bpmn-js грузятся с CDN);
- `mindmap.md` — майндкарта в Markdown;
- `processes/*.bpmn` — схемы, открываются в Camunda Modeler, bpmn.io или Bitrix24/amoCRM-совместимых редакторах BPMN.

## Правила модели

- У каждого шага и проблемы есть `source`: `stated` — клиент сказал прямо, `inferred` — достроено. Всё `inferred` помечается «(?)» и показывается клиенту на подтверждение.
- Шаги процесса: `start`, `task`, `decision`, `wait`, `message`, `end`. Роль шага (`role_id`) = дорожка на BPMN.
- Проблемные шаги (`issues` со `step_id`) подсвечиваются на схеме: красный — критично/высоко, оранжевый — средне. Жёлтый — ручная операция (`is_manual`).

## Дорожная карта

1. ✅ Ядро: модель → майндкарта, BPMN, отчёт
2. Ручной режим: ответы клиента → модель (через Claude вручную)
3. Telegram-бот для интервью
4. Публикация отчёта по ссылке
5. Подключение нейронки по API для автоматического разбора
