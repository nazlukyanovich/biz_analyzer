# biz_analyzer

Сервис разбора бизнеса: клиент проходит интервью, из ответов собирается модель бизнеса, а из неё — майндкарта, BPMN-схемы процессов и отчёт с узкими местами.

## Как устроено

```
интервью (questionnaire.yaml)
        ↓
модель бизнеса (JSON по business_model.schema.json)
        ↓  core/validate.py — проверка схемы и ссылок
        ├─ core/mindmap.py → майндкарта (Markdown, рендер через markmap)
        ├─ core/bpmn.py    → BPMN 2.0 XML по каждому процессу (своя авторазметка)
        └─ core/report.py  → HTML-отчёт для клиента
```

| Папка | Что внутри |
|---|---|
| `schema/` | Схема модели бизнеса и анкета интервью |
| `core/` | Проверка модели и генераторы |
| `examples/` | Демо-модели для проверки генераторов |
| `industries/` | Справки по отраслям для персональных вопросов бота |

## Запуск

```bash
pip install -r requirements.txt
python -m core.build examples/flower_delivery.json -o out/flower_delivery
```

Результат в `out/flower_delivery/`:
- `report.html` — отчёт, открыть в браузере (нужен интернет: markmap и bpmn-js грузятся с CDN);
- `mindmap.md` — майндкарта в Markdown;
- `processes/*.bpmn` — схемы, открываются в Camunda Modeler, bpmn.io или Bitrix24/amoCRM-совместимых редакторах BPMN.

## Telegram-бот (интервью)

Бот задаёт вопросы из `schema/questionnaire.yaml` по одному. Если ответ короткий, без цифр там, где они нужны, или размытый («по-разному», «всё делает менеджер»), бот задаёт уточнение (не больше двух подряд). По процессам продаж и выполнения заказа задаёт углубляющие вопросы и пропускает те, на которые клиент уже ответил. Когда интервью закончено, ответы сохраняются в `data/answers/` (`.md` для чтения, `.json` для разбора), а бот присылает их владельцу.

1. Создать бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопировать токен.
2. Скопировать `.env.example` в `.env` и вписать `BOT_TOKEN`.
3. Запустить:
   ```bash
   pip install -r requirements.txt
   python -m bot.main
   ```
4. Написать боту `/myid`, вписать полученное число в `ADMIN_CHAT_ID` в `.env` и перезапустить бота. Теперь готовые ответы клиентов будут приходить тебе файлами.

Команды бота: `/start` — начать или продолжить, `/back` — вернуться к прошлому вопросу, `/skip` — пропустить вопрос, `/status` — как дела с разбором, `/restart` — начать заново. Для владельца (чат из `ADMIN_CHAT_ID`) ещё `/report`. Под каждым вопросом есть кнопки «Назад» и «Пропустить».

Как устроен путь клиента:
1. **Согласие на обработку данных** — пока выключено. С `CONSENT_REQUIRED=1` в `.env` вопросы начинаются только после кнопки «Согласен», а «Подробнее» показывает, что и зачем собираем (или ведёт на `PRIVACY_URL`, если задан).
2. **Режим**: ⚡ экспресс — 10 главных вопросов (список `express` в анкете), одно уточнение, без углубления, около 5 минут; 🔍 полный разбор — все вопросы, уточнения и вопросы из справки по отрасли.
3. **Интервью**. Перед каждым ответом бот на секунду показывает «печатает…».
4. **Контакт** — в конце бот просит номер кнопкой «Отправить номер» или любой способ связи текстом; можно пропустить.
5. **Напоминания** — если клиент бросил интервью, бот напишет через сутки и через трое суток (только с 10 до 20 по Минску/Москве), не больше двух раз. Сроки — `REMINDER_HOURS` в `.env`.
6. **Статус разбора**: после интервью клиент видит, что разбор будет готов в течение 2 рабочих дней, а `/status` показывает, готовится он или уже готов. Тебе вместе с ответами приходит готовая команда `/report <chat_id> ссылка` — она отправит клиенту ссылку на отчёт.


### Голосовые ответы

Голосовые распознаются через Yandex SpeechKit (`bot/transcriber.py`): до 30 секунд — синхронно за пару секунд, длиннее — асинхронно (около 10 секунд на минуту голоса). Бот показывает распознанный текст с кнопкой «Переписать ответ», если что-то услышал не так.

Чтобы включить: в Yandex Cloud создать сервисный аккаунт с ролью `ai.speechkit-stt.user`, выпустить для него API-ключ и вписать его в `YANDEX_API_KEY` в `.env`. Без ключа бот работает только с текстом.

Уточнения сейчас работают по правилам (`bot/clarifier.py`), без нейронки. Чтобы подключить нейронку, достаточно написать ещё одну реализацию `Clarifier` с тем же методом `clarify`.

### Справки по отраслям

В `industries/` — 25 справок по отраслям с уклоном в отдел продаж: типичная воронка, где болит в продажах, что автоматизировать. По ответам первого блока бот узнаёт отрасль и добавляет вопросы из её справки — металлообработке про расчёт по чертежу, салону красоты про онлайн-запись и неявки. Формат — в [industries/README.md](industries/README.md).

Тесты логики интервью: `python -m unittest discover tests`

## Правила модели

- У каждого шага и проблемы есть `source`: `stated` — клиент сказал прямо, `inferred` — достроено. Всё `inferred` помечается «(?)» и показывается клиенту на подтверждение.
- Шаги процесса: `start`, `task`, `decision`, `wait`, `message`, `end`. Роль шага (`role_id`) = дорожка на BPMN.
- Проблемные шаги (`issues` со `step_id`) подсвечиваются на схеме: красный — критично/высоко, оранжевый — средне. Жёлтый — ручная операция (`is_manual`).

## Дорожная карта

1. ✅ Ядро: модель → майндкарта, BPMN, отчёт
2. Ручной режим: ответы клиента → модель (через Claude вручную)
3. ✅ Telegram-бот для интервью (уточнения по правилам)
4. Публикация отчёта по ссылке
5. Подключение нейронки по API для автоматического разбора
